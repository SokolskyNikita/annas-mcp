# OpenAlex in annas-mcp

Implemented locally on November 4, 2026. The live CLI/stdio checks retrieved AlphaFold, a Glasgow dissertation without a DOI, and a selected arXiv manuscript without a hosted OpenAlex PDF. They also verified cross-process file reuse and structured-text continuation. A separate live call retrieved the correct *The state of OA* PDF via AA after OpenAlex rejected the test key. For the shipped interfaces and reproducible checks, see the [usage guide](HOW-IT-WORKS.md), [Go SDK guide](papers/README.md) and [opt-in acceptance runner](scripts/test-paper-interfaces-live.mjs).

## What the user should be able to do

“Get me this paper” with a DOI should take one agent tool call and end with a path to the correct file, or a specific explanation and the best remaining access link. “Find me this thesis” should work from a title, author or topic, even when the thesis has no DOI. A citation lookup should return enough evidence to cite a work without downloading it. The full delivery includes discovery, copy inspection, hosted and direct open PDFs, AA fallback, reading from an agent, installation, and failure recovery.

The November 4, 2026 spot check gives us named cases to implement against. OpenAlex advertised cached PDFs for AlphaFold and the semaglutide outcomes paper. Its dissertation search also found two works with cached PDFs and no DOI. Authenticated HEAD requests for AlphaFold and the Glasgow thesis returned HTTP 200 and `application/pdf`. Those checks did not fetch the files. The earlier ten-paper comparison measured median DOI lookup at 1.16 s on OpenAlex and 8.12 s on Anna’s Archive (AA). Benchmark actual file retrieval separately from metadata or advertised availability. [AlphaFold](https://openalex.org/W3177828909) · [Semaglutide](https://openalex.org/W4388592674) · [Glasgow thesis](https://openalex.org/W1588575005) · [Hull thesis](https://openalex.org/W2954100343)

## 1. Start from the agent’s task

| Request or situation | Shortest supported interaction | What the agent can tell the user |
| --- | --- | --- |
| “Download this DOI, W ID or OpenAlex work URL” | Call `article_download` directly. Resolution, verification and eligible fallback happen inside the call. | File path, source, and version if known, or why the file could not be supplied. |
| “Get the paper by these authors,” a pasted citation, or a misspelled title | Call `article_search` with the title and available author/year. Compare returned identities and use the selected hit’s `download_args`. If several materially different works fit, present the alternatives. | Correct paper in two calls when unambiguous. If the user must choose, show the distinguishing title, author, year or venue. |
| “Find dissertations on X from this repository” | Search with `work_type=dissertation` and optionally a repository ID. Pass the W ID or the returned download arguments through unchanged. | Thesis title, author, repository, access evidence and file or landing page. A repository or author affiliation alone does not establish which university awarded the degree. |
| “Is this the published version?” or “Get this specific copy” | Call `article_details`. Select a location by the returned arguments or request a strict version on download. | Which copy is known to match, which is available only as a manuscript, and which has unknown version. |
| “Give me the citation,” “Who cites this?” or “Find related papers” | Exact search/details for the citation. Use a relation filter on `article_search` for one page of citing, referenced or related works. | Bibliographic fields and canonical link, or a pageable list. Search and details issue no content GETs. |
| “Read or summarize this paper” | Prefer a readable local PDF if the agent shares the server’s filesystem. Otherwise use the bounded `article_read` path when structured full text is available. | A passage with work and section provenance. If only the abstract was accessible, explicitly describe it as an abstract. |
| “Get this exact AA file,” book, standard or edition | Keep the existing hash, book and catalog flows. When a book/catalog result identifies a paper by DOI, hand that DOI to the article tools. | The chosen file or edition, retaining its existing integrity checks and AA-specific evidence. |
| “Next page,” “get these five,” or “try that one again” | Replay returned paging arguments. Run individual selected downloads with bounded parallelism. Preserve successes if one fails. Repeats verify existing files before a metered GET. | A result per work, including reuse, fallback, missing files and any retry time. |
| “Set it up,” “why didn’t it download?” | Initialize and list tools locally. For diagnosis use provider-aware `account_status` or the specific action returned with the failure. | Which credential or limit matters, which provider was attempted, and whether a useful copy or link remains. |

## 2. Define one contract for MCP, CLI and Go

Retain the existing tool names and add two with distinct jobs. The CLI uses the hyphenated equivalents. Ordinary paper requests work with defaults. Advanced controls appear in the schemas and command help.

| Surface | Proposed inputs and result |
| --- | --- |
| `article_search` | Keep `query` for keywords, pasted citation text, DOI or W ID/URL. Add article-only `provider`, `work_type`, `author_id`, `institution_id`, `repository_id`, and optional `relation` plus `work_id`. Exact ID returns one record as today. Text, filters and relations return a page. |
| `article_details` | One `id` (DOI, W ID/URL, or AA MD5/page URL) and optional provider. Return identifiers, ordered authors, title, year/date, venue/repository, type, canonical citation link, abstract if available, citation count, and a bounded list of locations with replayable copy selections. Page additional locations on demand. Reuse AA lookup/details for AA records. |
| `article_download` | Exactly one of `doi`, `openalex_id` (W ID or work URL), or existing `hash`. Preserve the positional DOI, `--hash`, title override and timeout. A positional W ID/URL is also accepted. Add optional `provider`, `location_id`, `version` and `artifact=pdf\|tei_xml`. Default OpenAlex artifact is PDF. Explicit location/version constrains the result. |
| `article_read` | One DOI or W ID, optional opaque continuation. Return a bounded passage of OpenAlex structured text with title, section heading, work link, source and next arguments. The first request may fetch TEI and consume content allowance. Describe that cost in the tool itself. If TEI is unavailable, return the available abstract or PDF route as a clearly labeled alternative. |
| `account_status` | Add optional `provider=anna\|openalex`. Preserve the existing AA response by default when AA is configured. With only an OpenAlex key, default to OpenAlex. An explicit OpenAlex check reads its rate-limit endpoint and returns reported units and reset time. Omit unknown fields. Status is a diagnostic, never a prerequisite to retrieval. [Authentication and usage](https://help.openalex.org/api/authentication/) |
| Go callers | Keep existing `anna.Client` methods, errors and exact-file semantics. Expose the coordinated article operations in a sibling `papers` package with explicit configuration, context, optional progress and typed results/errors. CLI and MCP call that implementation. A Go agent gets provider fallback and copy selection without implementing its own. |

**Output the next call in the format the agent can use.** Search hits carry `provider`, citation identity, access summary, a canonical user-facing URL, `details_args`, and `download_args` when a supported route exists. A selected W ID can use verified DOI fallback in auto mode. Pinned AA files use their hash. Landing-only records expose a link and details. Do not manufacture download arguments for an unsupported file. The Glasgow hit illustrates the fields an agent needs.

```json
{
  "provider": "openalex",
  "openalex_id": "W1588575005",
  "title": "Functional programming and graph algorithms",
  "work_type": "dissertation",
  "access": ["hosted_pdf", "repository_pdf"],
  "details_args": {"id": "W1588575005"},
  "download_args": {"openalex_id": "W1588575005"}
}
```

Keep default pages compact. Include title, short author display, year, type, venue/repository, identifiers and access evidence. Put full authorship, ORCIDs, abstract, copy versions/licenses and location IDs in details. Keep AA’s `fast_download`, `stats`, `partial_matches` and exact hash meanings. A citation count is work-level metadata. An AA download count describes one file. Distinguish a hosted PDF, reported external PDF, AA route, landing page and no known access. Only a completed transfer or revalidated local file supports a claim that the work was downloaded.

A successful download keeps `path`, `bytes` and optional AA `downloads_left`. Add `provider`, `route`, stable work/file identity, `mime_type`, `reused`, observed digest and known copy/version evidence. Return a short fallback reason when it explains the result. Return an absolute path on the **server host** and a canonical public work/landing URL. In Docker, document mounting the output directory. In a host without shared storage, offer bounded reading or the public link. An agent must never present an inaccessible server path as a client attachment.

### Example interactions to ship and test

A caller with the DOI and a download request goes straight to the downloader. These are equivalent proposed MCP and CLI inputs.

```json
{"name":"article_download","arguments":{"doi":"10.1038/s41586-021-03819-2"}}
```

```sh
annas-cli article-download 10.1038/s41586-021-03819-2 --json
```

For a thesis, search and replay the chosen hit. The W ID is enough even after restarting the client.

```sh
annas-cli article-search 'graph algorithms' --work-type dissertation --limit 5 --json
annas-cli article-download --openalex-id W1588575005 --json
```

For an ambiguous copy, fetch details and pass through the selected location ID verbatim. For a terminal miss, an agent should be able to answer, for example, “I found the thesis record and its university repository page. Neither configured source supplied a PDF.” Include the actual landing page in that response. For a successful AA fallback, the same agent should be able to say which source delivered the file without inspecting debug logs.

## 3. Implement discovery and identity

Implement the official Works API directly. Exact lookups accept bare or prefixed DOI, doi.org URL, W ID and openalex.org work URL. Normalize IDs before building fixed-host requests and retain the surviving W ID after a merge. For DOI matches, check primary and location DOIs. Keep the requested DOI and the canonical record’s DOI distinct. A work can group a preprint and publication. A work-level hosted file has unknown version unless the API provides evidence specific to those bytes. For an alternate DOI tied to a specific version, require a matching location or report the ambiguity before substituting. Searching by title must never silently authorize a download of a different work. [Singletons](https://help.openalex.org/api/get-single-entities/) · [DOIs and versions](https://help.openalex.org/data/works/dois/)

| Input | OpenAlex behavior |
| --- | --- |
| Keywords, title, author | Use `search` for topics and `search.title` for a title constraint. A quoted `raw_author_name.search` matches a byline. Support an exact OpenAlex author ID or ORCID for disambiguation. Escape filter syntax as well as URL parameters. [Search](https://help.openalex.org/api/searching/) |
| Work type | Default ordinary-paper pool includes articles, reviews, preprints and conference papers. Support explicit types including dissertation, and an `any` option. Use `type:dissertation&corpus=all` for theses, including older repository deposits. Both doctoral and master’s theses can carry this type. [Types](https://help.openalex.org/data/work-types/) · [Corpus](https://help.openalex.org/data/works/corpus/) |
| Year, language, institution, repository | Support exact year and inclusive year range on OpenAlex. Language describes the indexed metadata. Map affiliation to `institutions.id` and repository to `repository:S…`. Expose relevant IDs in details so agents can reuse them. Treat institution names in a free-text request as search evidence unless an ID is resolved. [Filter registry](https://api.openalex.org/properties/works) |
| Sort and relations | Support relevance for searches, newest/oldest and most cited. User-facing `relation=citing` maps to `cites:W…` and returns works citing the seed. `references` maps to `cited_by:W…` and returns the seed’s bibliography. `related` maps to `related_to:W…`. Require a seed for all three and test direction with a known citation pair. [Citations](https://help.openalex.org/data/works/citations/) |
| AA-specific controls | Existing collection `source`, publisher field as defined by AA, file size/added sorts, file format filter, AA content and file stats keep their AA meanings. In auto mode route them to AA. Reject incompatible explicit OpenAlex or mixed-only filters before HTTP. Tight version/location constraints belong to the selected download. |
| Paging and availability | Use one bounded list request with field selection per ordinary page, default 10 MCP hits, maximum 100 OpenAlex hits. Keep AA’s existing CLI limit semantics. Return provider-pinned `next_search_args` carrying the original filters, size and appropriate page/cursor. Treat cursors as opaque. Results and totals belong to one provider. For `downloadable_only`, hosted-only first release uses `has_content.pdf:true`. With external routes shipped, accept only hits with actual hosted evidence or an eligible direct PDF location. If filtering locally, page over the same upstream query with a bounded scan and continuation. Omit exact eligible totals when unknown and distinguish upstream count from returned hits. [Paging](https://help.openalex.org/api/paging/) |

For a list search, defer singleton lookup until the caller selects a record or asks for details. List responses can truncate locations. Read full locations for copy selection and reconstruct any supplied inverted abstract index only on demand. Default details should present a few useful locations with version, license, host, source and next actions. Preserve the upstream location ID verbatim, including punctuation. Verify it belongs to the selected canonical work each time it authorizes a download. [Work attributes](https://help.openalex.org/data/works/attributes/) · [Locations](https://help.openalex.org/data/locations/)

## 4. Make provider routing deterministic

| Request in `auto` | Rule |
| --- | --- |
| AA MD5 or AA file URL | Use AA directly. A conflicting explicit OpenAlex provider is invalid. |
| W ID/URL, OpenAlex relation, dissertation selector or OpenAlex-only field | Resolve through OpenAlex. If no key is configured, give setup instructions. For an unconstrained selected work, AA download fallback requires its verified DOI. No title-only fallback for a no-DOI thesis. |
| Ordinary DOI or keyword search | With an OpenAlex key, start there. With AA alone, retain existing AA behavior. For portable queries, try AA on an eligible OpenAlex error, exact miss or zero upstream matches on the first page. If ranked hits exist but none look convincing, return them and an explicit AA search option. A metadata-only hit is useful in a citation lookup. |
| Explicit provider, copy, version or artifact | Keep that constraint through all attempts. Reject `provider=anna` with W ID, OpenAlex-only controls or TEI. A selected location authorizes only that copy. Under a strict version, try other locations only if they independently prove that version. No silent substitution with an unknown-version PDF. |
| File format override | Preserve historical AA extension behavior on explicit AA requests. For an unconstrained DOI plus a non-PDF legacy extension, route to AA. For OpenAlex PDFs require an omitted extension or PDF. Use the separate artifact selector for TEI and the corresponding XML extension. |
| No configured provider or provider-only failure | Local help, version, handshake and tool listing still work. Give the name of the required environment variable for the requested operation. A malformed/expired AA credential must not block an OpenAlex-only flow, or vice versa. AA membership advice belongs to AA errors. |

For an ordinary DOI download, use this order under one caller deadline: verified local copy compatible with the request → hosted OpenAlex PDF → eligible direct open PDF from the selected work → existing AA DOI downloader. In AA-only mode preserve the existing AA order. Do not start two downloads speculatively or spend both allowances. Where the AA fallback record conflicts with the verified citation, withhold that candidate and return the conflict. Do not silently accept the first similar title. A confirmed no-file result should retain the best landing page, work identity and available alternative actions.

Report provider attempts separately inside one outcome. Preserve existing public error categories and add machine-readable `provider`, `reason`, `retryable`, optional `retry_after`, work/landing link and bounded `next_actions`. Explicitly handle missing key, unauthorized, daily budget exhausted, transient throttle, unavailable provider, work missing, found with no copy, version mismatch, corrupt file, cancellation and local I/O. In auto mode try the next eligible provider for upstream failures. Keep the original reason even if AA also fails. Stop on cancellation, deadline or local disk error. A useful empty search page is a successful search.

**Who resolves the actual download URL?** The agent supplies identity. The provider supplying the file resolves access. OpenAlex can return a DOI, its own hosted content endpoint, or an open location. None supplies an AA MD5 or signed AA URL. On AA fallback the existing `DownloadArticle(doi)` consults SciDB, searches AA’s indexes when necessary, resolves the hash or embedded PDF, and obtains AA’s member-specific download URL. Keep those requests and credential checks inside the one agent call. When just a title is known, search and compare records before selecting a work. [AA DOI lookup](anna/doi_lookup.go) · [AA download and grant resolution](anna/client_download.go)

## 5. Implement file access and reading

1. **OpenAlex-hosted PDF.** Fetch the selected work’s `content_urls.pdf` when `has_content.pdf` is true. Authenticate only to the official API/content hosts. Stream the selected artifact once. Search, details and status never GET content. For an explicit read/download, avoid a preliminary HEAD and duplicate GET. Treat work identity, copy/version evidence and byte integrity as separate facts. A matching PDF signature alone cannot verify the paper’s identity. [Content fields](https://help.openalex.org/data/works/attributes/)
2. **Open PDFs at repositories and publishers.** Ship direct retrieval for explicit open HTTPS `locations[].pdf_url` links. Refetch the selected singleton, match the requested DOI/version first, and prefer a repository for theses. Otherwise order eligible copies deterministically by version (published, accepted, submitted, unknown), then source and stable location ID. Try at most two distinct URLs automatically under the remaining deadline. Try only the chosen location when pinned. Mark host-reported availability as unverified until retrieval. Preserve a usable landing link when a host serves HTML, challenges access or lacks a direct URL. Use a credential-free client, cap redirects, enforce public destination addresses when dialing and on redirect, and reject userinfo, private or local destinations. This covers direct publisher PDFs without introducing publisher-page scraping. [Locations](https://help.openalex.org/data/locations/)
3. **Durable local files.** Factor the smallest common bounded writer out of AA. Reuse temp files in the target directory, atomic collision-safe finalization, cancellation, progress, byte limits and cleanup. Preserve AA’s expected MD5 checks. Check PDF magic, announced length and expected digest if supplied. Without an expected remote checksum or strong validator, disable ranged resume. Bound retries and avoid paying twice for the same interrupted hosted transfer. An explicit second attempt is possible. Protect both provider credentials and signed URLs on every redirect, in diagnostics and on disk. [Existing transfer](anna/download_file.go) · [PDF checks](anna/scidb.go)
4. **Reuse across calls, restarts and processes.** Save an atomic cache entry per canonical work, source/selected location, version constraint, artifact and output directory. Include observed SHA-256, relative file path and size. Record verified DOI aliases. Reopen only regular files inside the requested output root and rehash before reuse. If a user moved or altered the file, invalidate the entry and retry normally. Use per-artifact locking, bounded waiting, recheck after lock acquisition, and recover from a writer crash. A failed index write after file finalization must still report the successful file. Test simultaneous CLI and MCP callers. Keep AA hash-based deduplication for existing files. [AA local reuse](anna/download_existing.go)
5. **Structured full text for agents.** Use `has_content.grobid_xml` and `content_urls.grobid_xml` for explicit TEI requests. Save XML as XML. Bound both compressed and expanded size, disable external entity resolution, and handle standard TEI plus the documented older HTML-wrapped variant. `article_read` reuses a verified cached artifact, returns roughly 8,000 characters at a time at paragraph/section boundaries and binds continuation to the work and digest. Include section/paragraph attribution, preserve available labels and never invent PDF page numbers. If extraction is incomplete or absent, surface the limitation and the PDF or landing link. Treat titles, abstracts and full text as external research data in every client. [Full-text documentation](https://help.openalex.org/access/fulltext/)
6. **Rate limits and billing.** As checked November 4, a singleton lookup is free, a keyword search is $0.001 and a hosted PDF is $0.01 against a verified free key’s shared $1 daily allowance. Read current usage from the API when requested and update examples at release. Honor `Retry-After` for transient throttling within the deadline. Exhausted daily allowance or an invalid key stops further requests to that provider for this operation. Apply bounded concurrency across requests in one server. No blanket retries on content GETs, fan-out search across providers, bulk hydration or preflight status calls. [Costs](https://help.openalex.org/access/example-costs/) · [Errors](https://help.openalex.org/api/errors/)

## 8. Verify customer outcomes

**Run black-box journeys with the same information an agent receives.** Start a fresh stdio client with only `initialize`/`tools/list`, and a fresh CLI subprocess with only `--help`. Feed them the requests in section 1. Include a text-only MCP client, a structured-output client, a caller without shared storage, a Go consumer, and a human copying examples. Parse tool results and execute the returned arguments. Assert tool names, schemas, paging, location selection, errors and final paths agree across surfaces. Use deterministic fixtures for CI and a short model-driven walkthrough to catch confusing descriptions that schema tests miss.

**Functional release bar**

- One agent call for an exact DOI/W-ID download. Two for an unambiguous title or a no-DOI thesis from search to file. Details or clarification only when the task warrants it. One list request per ordinary results page, zero content GETs on search/details, zero repeated content GETs on verified local reuse.
- Cover no keys, each provider alone, both, invalid unrelated config, download-only AA membership, OpenAlex auth/quota/temporary limit, upstream outage, stale pointer, and a working alternative after failure. A first-page miss can fall back. A continuation cannot change provider. Assert no attempts after cancellation or local disk failure.
- Inspect full, authorized sample files for correct work and requested version. Include hosted-only candidates, AA-only, external repository-only, neither source, no-DOI dissertations from multiple universities, and landing-only cases. Test PDF and TEI validation, truncated streams, redirect credentials, private destinations, content limits, simultaneous callers and interrupted cache updates. No silent wrong-work or wrong-version selections in the fixture or live acceptance sets.
- Compare AA alone, hosted OpenAlex alone, hosted plus direct PDFs, and the full sequence. Report incremental correct files over AA alone separately from correct files obtained without an AA membership. Separate paper and dissertation results. Record calls to completion, p50/p95 latency, bytes returned to the agent, cost per successful file, unnecessary status/detail calls, user clarification and actionable recovery. Use a declared, bounded live budget. Do not convert a small handpicked sample into a general coverage claim.
